## Evidence (reproducible: `tests/test_real_data_scope.py`)

* The real log is `data/raw/vbfa_o2c_2019_2021_eur.jsonocel` (SAP document flow, 4,811 events,
  11 activity types, e.g. `Create Invoice (from Order)`).
* Every event carries only: `quantity, unit, value, currency, material, movement_type, billing_category`.
  There is **no** unit price, discount rate, tax rate, FX rate, posting amount or rounding rule.
* `policy_engine.unmapped_activities` on all 11 VBFA activities returns all 11: **no VBFA activity
  maps to a correction function.**
* Consequence, observed on the real cases `e977` and `e34`: `build_case` does **not** raise. Every
  candidate silently becomes a null "context" node, there are zero active players, the observed state
  already equals the compliant state, and loss = 0. A pipeline that ran stages 3–5 on this would
  report "PASS, nothing to attribute", which is a false result, not a finding.

## Decision

| Data | Stages | Role in the evaluation |
|---|---|---|
| Real VBFA cases (`e977`, `e34`, ...) | 1, 2, 2b (extraction, candidates, structural order locks) | **Qualitative** validation: the method runs on production-shaped SAP data. Real finding: SAP batch commits give identical timestamps (`e977`: 28 permutable pairs among 8 siblings). |
| Benchmark cases (`RSC-2026-xxxxx`, synthetic, hidden ground truth) | 1 – 5 (replay, confluence verdict, attribution, evidence) | **Quantitative** validation: correctness measured against known truth. |

Rules that follow from this:

1. Stages 3–5 are **not applicable** to a VBFA case. The API/UI must say so
   (`ReplayOperator.is_replayable == False`), never show a PASS or a zero attribution.
   The edit/replay endpoints already answer HTTP 422 for VBFA ids.
2. Every benchmark case is labelled `benchmark (synthetic)` in the API and must be labelled so in the UI and report.
3. We do not claim a verdict, a loss or an attribution for any real VBFA event.

## Limitations to state openly in the report / defense

* No real-data ground truth exists for counterfactual losses (the real world does not record what
  would have happened), so real-data evaluation is necessarily qualitative.
* The benchmark tests the mechanism under known conditions; it is generated by Member 2 and graded by
  her independent oracle, so it reflects her modelling assumptions (frozen domain, 7 families).
* Public OCEL 2.0 logs (Order Management, Procure-to-Pay) are simulated, and none ships with
  discount/tax/FX policy data or deviation ground truth.

## Optional stretch (only after the confluence checker passes the full benchmark)

A clearly labelled **semi-synthetic overlay** on `e977`: a sidecar file assigning invented pricing
fields to its 8 real candidate events, a reference contract and a policy, so one real event structure
runs through all five stages. Needs Member 2 (activity → correction mapping, ground truth via her
oracle). Results would demonstrate the mechanism on real structure, not real losses.
